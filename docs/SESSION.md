# Zirel: журнал сессии

## Текущая синхронизация

Дата: 2026-07-05

## Что было обнаружено

- Проект является Flask-монолитом.
- Официальное название текущего проекта: Zirel.
- Реализован режим списка ожидания через `WISHLIST_MODE`.
- Реализованы аккаунты пользователей, защищенные маршруты проектов и админские маршруты.
- Основное рабочее пространство уже содержит проекты, персонажей, фракции, события, связи, предупреждения, граф, импорт и экспорт.
- Есть публичные страницы: wishlist/landing, beta, FAQ, roadmap, whitepaper, legal pages, feedback, contact.
- Есть production-настройка для Render через `wsgi.py`, Gunicorn и поддержку PostgreSQL.

## Базовая точка проекта

Эта синхронизация подтверждена пользователем как текущая базовая точка проекта.

База является изменчивой: по мере подтвержденных изменений документация должна обновляться вместе с кодом.

## Текущее состояние проекта

Проект находится в состоянии MVP / ранней pre-launch beta.

Рабочая функциональность:

- регистрация и вход;
- приватные проекты пользователей;
- админ-панель;
- CRUD для ключевых данных мира;
- конструктор связей;
- динамические логические предупреждения;
- интерактивный граф мира;
- переносимость данных через JSON;
- сбор заявок в список ожидания;
- публичные информационные страницы.

## Недавние подтвержденные изменения

- Страницы Sign In / Sign Up были переработаны по предоставленным modal-референсам.
- Внешний trust footer под auth-карточками убран.
- В auth-карточках добавлена нижняя security/value строка.
- Убраны декоративные иконки из обычных полей.
- Оставлена кнопка-глаз для показа/скрытия пароля.
- Убран значок замка из нижней строки auth-карточек.
- Нижние надписи в auth-карточках сделаны крупнее и просторнее.
- Создана базовая документация проекта в `docs/`.

Пользователь подтвердил текущий вид Sign In / Sign Up как рабочий вариант, но отметил, что к нему нужно будет вернуться позже.

## Что требует уточнения

- Нужно ли публично оставлять `/login` видимым в режиме списка ожидания или оставить маршрут доступным только по прямому URL для администратора.
- Финальное поведение `/register` во время режима списка ожидания.
- Финальный домен и переменные окружения production на Render.
- Когда именно фиксировать изменения через git commit/push.

## Рекомендуемые следующие шаги

1. Сделать commit/push подтвержденных изменений.
2. Затем перейти к переработке Terms / Privacy / Disclaimer.
3. Позже вернуться к дополнительной полировке Sign In / Sign Up.
4. После каждого подтвержденного этапа обновлять `SESSION.md`.
5. `CHANGELOG.md` обновлять только после подтверждения пользователя.
